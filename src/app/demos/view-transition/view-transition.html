View Transition

The @view-transition at-rule opts a page into cross-document view transitions. When a user follows a same-origin link, the browser snapshots the outgoing and incoming pages and animates between them using ::view-transition-old and ::view-transition-new — entirely in CSS, with no document.startViewTransition() call anywhere. 

@view-transition {
  navigation: auto;
}

.card {
  view-transition-name: card;
}

.badge {
  view-transition-name: badge;
  /* 64px on page A, 128px on page B */
}

::view-transition-old(card) {
  animation: fade-slide-out .35s ease-in both;
}

::view-transition-new(card) {
  animation: fade-slide-in .35s ease-out both;
}

Because @view-transition only activates on real cross-document, same-origin navigations, this demo embeds two standalone HTML pages in an iframe below. Click the link inside the frame to navigate between them with plain <a href> tags — the fade/slide you see is driven purely by the CSS shown above.

  • Cross-document view transitions require both pages to be same-origin and both must opt in via @view-transition { navigation: auto; }.
  • Elements that share a view-transition-name on both pages are matched automatically and morph between their captured states — the badge image goes from 64×64 to 128×128 with a smooth size animation, purely because both pages gave it the same view-transition-name.
  • There is no JavaScript involved in triggering or driving the transition — it happens purely because the browser navigated to a new document.
